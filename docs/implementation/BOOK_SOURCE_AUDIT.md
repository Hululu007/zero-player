全站聚合并非仅存在于合成测试：随包记录 4560「你的地址1」同时声明“全部”、普通“言情小说”和受限“百合肉文”分类；记录 1241「御书屋网」同时声明“全部”、普通“玄幻”和受限“肉文”分类。可从来源包对应记录的 `exploreUrl` 与台账的选中索引离线复核；这是随包规则证据，未据此断言当前网页内容。

### 补扫页面结果到 eval

此前按同一字段同时出现网络词与 `eval` 粗筛，会漏掉直接处理已获取页面的规则。新增的[宽泛候选清单](legado-response-eval-candidates-20261115.json)对选中原始版本检查 `eval` 与 `result`、`src` 等页面变量或 `java.getString` 同字段共现，得到 85 个 ID，其中 51 个不在先前网络词候选中。共现只是筛选信号，可能是本地元数据求值或无关变量，不能直接当成数据流或恶意代码。

其中 34 个选中 ID 的规则经静态逐字段核对，确实包含把网页结果、脚本片段、匹配表达式或响应字段交给 `eval` 的路径；部分原本意图解析图片数组、章节顺序或其他数据。[原始字段证据](legado-response-eval-triage-20261115.json)和[实际导入后的字段摘要](legado-response-eval-normalized-20261115.json)记录了对应版本。应用按精确字段摘要隔离这些旧规则及其无来源信息的历史记录，来源修订后可主动导入且默认停用；相同危险片段搬到其他可执行规则、搜索／发现地址或脚本库时仍受限。涉及注释的组合仍需同时匹配特定注释及其调用脚本，不能仅凭注释本身隔离。不因此封禁整个域名或断言页面已挂马，未执行这些规则。

历史来源被删除后，同一旧式 ID 可能因 `www` 规范化而指向另一个主机；现在不同主机的来源不能为已隔离 ID 的旧书解除限制，原有离线文件保留。相同主机的旧缓存没有规则版本指纹，自动或人工换规则也不能证明它来自哪一版；若需要严格区分旧缓存与新作品，仍需增加带授权的历史来源证明，不能把本次限制视为完整缓存溯源。

对新增 51 个候选中的其余 17 个，以及两条未命中上述筛选、但对来源元数据求值的规则，静态检查其调用入口和相关字段；当前选中版本中未发现网页或网络响应进入这些 `eval` 的证据，不仅因这一信号隔离。[逐 ID 复核](legado-local-eval-review-20261115.json)记录各字段摘要与结论；固定打包字面量仅作文本替换展开，未执行来源代码。这一结论不代表站点或其他规则安全、可用，也不排除不在本次字段范围内的数据流。
