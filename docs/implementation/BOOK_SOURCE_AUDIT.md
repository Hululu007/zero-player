使用本机 Windows Defender 及 AMSI 对 2010 个入口主机的根页面进行独立、有界采样，不跟随跳转、不执行脚本、不读取外链，也不保存网页内容。432 个主机取得非空 HTML 且扫描接口成功，关联旧导入清单 511 个来源 ID；其中 415 个根页面未检出、17 个检出，182 个样本因长度上限被截断。其余 1578 个主机因超时、DNS、跳转、TLS 等原因没有成功扫描 HTML。另对 1021 段有限长度内联脚本分别扫描，2 段检出，144 段因数量上限未扫描。完整时间、失败分类、样本摘要和各阶段证据见[扫描汇总](legado-amsi-summary-20261115.json)。本地接口对原始无害 EICAR 测试串可检出，但对嵌入 HTML 和脚本文本的相同测试串均未检出；因此“未检出”尤其不能当作排除木马的证据。现有杀毒产品设置可能使用云端保护或样本提交。

17 个首次检出主机再次取样时，15 个根页重现检出，另 2 个返回 HTTP 429。15 个中 14 个具有同一归一化页面结构，静态导航目标均为各自原主机的 HTTPS 根路径；这些主机的证书和连接地址摘要各不相同，其共同形态可能来自站点、CDN、WAF 或网络路径，无法确认归属。该组涉及首次导入清单中的 11 个选中 ID；结构归一化本身可能把不同行为归为一类。逐主机复查和形态摘要见[检出聚类](legado-amsi-template-clusters-20261115.json)，目前不据此批量固定隔离或断定存在挂马。

用当前导入器重新关联这 11 个 ID：1 个同时受既有成人与固定主机隔离限制，1 个受成人过滤限制，其余 9 个在没有用户本地阻断等其他限制时可在普通模式手动启用；逐 ID 关联和代码摘要见[来源分类](legado-amsi-source-classification-20261115.json)。新导入均默认停用。源管理对首次检出的 17 个精确主机显示带日期的历史检出提示并提供筛选，不自动封禁，也不因后续普通抽查而删除这项历史提示；再次看到提示应结合当前页面和规则人工复核。

## 来源规则中的远程脚本候选

对全部原始记录递归检查字符串，在同一字段同时出现 `eval(` 与网络相关词的共有 58 条原始记录；其中 53 条可单独导入，涉及 41 个唯一来源 ID。此为宽泛字符串共现，有可能只是正常脚本解包、示例或字段中无关的网络地址，**不能将 58 条直接判为下载后执行，更不能据此断言网站挂马**。

其中 3 条经逐字段静态核对属于同一 `wesrc` 模板：原始记录 535（`souxs.leeyegy.com`）、2088（`www.qklady.com`）、2504（`wap.maxreader.la`）。每条的 `ruleSearch.bookList` 和 `ruleContent.content` 都使用 Android `Packages.okhttp3` 请求 `http://yck.hr7t4h.cn/yck/funcs`，将响应保存为 `global.wesrc`，经 Android Base64 解码后传入 `eval`。当前应用的 QuickJS 运行时不提供这些 Android 原生接口；这仍是不可信的来源规则，不是网站已被植入木马的证据。未执行这些规则，也未请求该第三方地址。三个完整 ID、各字段摘要、其他宽泛候选与静态线索见 [规则模式结果](legado-rule-patterns-20261115.json)。应用按危险规则的组合特征隔离，缺少原来源信息的这三个历史 ID 也受限；不扩大到同域其他来源。记录 535 的同 ID 较新版本 1798 未发现该模式，故不因旧版本而自动禁用；这不代表新版本已通过安全审核。

### 逐 ID 数据流细分

对 41 个可导入候选 ID 的全部候选记录及相关字段做静态复核，结果保存在 [逐 ID 分类及原始字段摘要](legado-eval-triage-20261115.json)。其中 32 个 ID 至少一个原始版本存在网络响应或网页提取值进入 `eval` 的数据流；2 个仅旧版本命中，修复前七包合并实际选中版本分别是 1798 和 4135，不能将旧规则直接归因给选中版本。其余 6 个目前只看到执行源自身元数据或固定分类表达式，3 个依赖缓存变量／未取回的外部库，数据来源尚不能确认。此结果不是恶意判定，也不证明分支已运行。

按 30 个选中记录的静态证据细分，12 个含网络脚本或网页脚本片段求值，2 个含第三方 Base64 脚本模板，1 个将页面属性提取结果交给 `eval`，13 个把预期的 JSONP／对象字面量作为表达式解析，3 个把页面或 JSON 响应字段拼入代码表达式；类别可能重叠，数量不可相加为来源总数。比如酷我规则中 `freetype` 来自 `JSON.parse(java.ajax(...))`，又被拼入 `eval('sort'+type2+'.push(json)')`，未看到数值白名单；这表明表达式注入面，不证明实际收到或执行恶意响应。JSONP 等预期数据可优先研究有界解析替换；从远端获取完整脚本并求值的规则应单独复核或隔离。

两条匹配原始脚本 SHA 和站点规则的酷我文字源，现将该分类脚本替换为有界 JSON 解析与固定分类白名单，并修正章节地址；其他来源和自定义规则不套用。Windows 原生应用对两条来源分别获取 26 个分类、20 本分类结果、28 个搜索结果、1651 章目录和 3192 字免费正文（`.dart_tool/native-64d721ae/legado_kuwo_native_test.log`）。分类出现未审核的 ID 或名称时会报错，需重新核对，不能将此次样本作为长期可用保证。

已修复的酷我和语雀原版不命中隔离；若其他改动使精确修复不再生效，保留旧危险分类脚本或旧注释及已确认调用者的变体仍会受限。酷我旧脚本在当前桥接中因不支持 `cache.getFile` 而无法走到后续动态求值，该项是预防性隔离，不表示已实际执行。

应用已按规范化字段的确切 SHA-256 对上述远端脚本片段和页面属性求值旧版本实施隔离；进一步核对后，剩余 12 个把预期 JSONP／对象表达式或网页字段交给 `eval` 的选中旧版本也按摘要隔离。其中两个固定请求目标跨出来源主机，当前同域限制会先拒绝请求；这一隔离属于预防性处理，不表示该响应已在本应用执行。涉及注释的规则还需同时匹配该注释的已确认调用脚本，单独的注释不触发隔离。对应无来源信息的旧书也会受限；若之后导入同 ID 的不同规则版本，旧缓存并不携带规则指纹，不能由新版本的可用性推断旧缓存已经审核。

使用当前应用导入器对上述选中版本做本地规范化复核，结果及导入代码摘要见 [规范化字段结果](legado-eval-normalized-20261115.json)：26 个 ID 的相应 `legado.rules` 或发现分类地址仍含 `eval`；另 4 个的危险数据流出现在 `legado.comment` 中，并有规则显式调用 `eval(source.bookSourceComment)`；还有 1 个 ID 同时具备上述两类，故 26 + 4 = 30。`comment` 本身是元数据，不是独立执行入口；结果单列了实际规范化后引用它的规则字段和摘要。静态代码存在和接口能够执行是两回事：部分原规则依赖本应用未提供的 Java／Android 接口或特定分支，此处没有运行来源脚本，也未证明运行可达。

本范围内未发现 `Function(...)` 或 `new Function(...)` 调用；对全部原始记录的同字段粗扫也未发现 Function 与网络标记同时出现。该扫描不是形式化数据流证明，未覆盖所有可能的拼写、间接调用或不在本候选集合中的跨字段数据流。

### 补扫页面结果到 eval

此前按同一字段同时出现网络词与 `eval` 粗筛，会漏掉直接处理已获取页面的规则。新增的[宽泛候选清单](legado-response-eval-candidates-20261115.json)对选中原始版本检查 `eval` 与 `result`、`src` 等页面变量或 `java.getString` 同字段共现，得到 85 个 ID，其中 51 个不在先前网络词候选中。共现只是筛选信号，可能是本地元数据求值或无关变量，不能直接当成数据流或恶意代码。

其中 34 个选中 ID 的规则经静态逐字段核对，确实包含把网页结果、脚本片段、匹配表达式或响应字段交给 `eval` 的路径；部分原本意图解析图片数组、章节顺序或其他数据。[原始字段证据](legado-response-eval-triage-20261115.json)和[实际导入后的字段摘要](legado-response-eval-normalized-20261115.json)记录了对应版本。应用按精确字段摘要隔离这些旧规则及其无来源信息的历史记录，来源修订后可主动导入且默认停用；相同危险片段搬到其他可执行规则、搜索／发现地址或脚本库时仍受限。涉及注释的组合仍需同时匹配特定注释及其调用脚本，不能仅凭注释本身隔离。不因此封禁整个域名或断言页面已挂马，未执行这些规则。

历史来源被删除后，同一旧式 ID 可能因 `www` 规范化而指向另一个主机；现在不同主机的来源不能为已隔离 ID 的旧书解除限制，原有离线文件保留。相同主机的旧缓存没有规则版本指纹，自动或人工换规则也不能证明它来自哪一版；若需要严格区分旧缓存与新作品，仍需增加带授权的历史来源证明，不能把本次限制视为完整缓存溯源。

对新增 51 个候选中的其余 17 个，以及两条未命中上述筛选、但对来源元数据求值的规则，静态检查其调用入口和相关字段；当前选中版本中未发现网页或网络响应进入这些 `eval` 的证据，不仅因这一信号隔离。[逐 ID 复核](legado-local-eval-review-20261115.json)记录各字段摘要与结论；固定打包字面量仅作文本替换展开，未执行来源代码。这一结论不代表站点或其他规则安全、可用，也不排除不在本次字段范围内的数据流。

语雀一条旧书单的页面数据求值现替换为有界 JSON／百分号解码，仅接受已审来源和旧规则摘要、同站固定书单 ID 与公开文档。Windows 原生应用实网取得 1 本发现结果、1 本搜索结果、23 个公开章节及 5191 字正文（`.dart_tool/native-3136e721/legado_yuque_native_test.log`）；目录或页面协议变更时可能需要重审。

探针仅读取已校验摘要的随包静态数据，不执行来源规则或页面脚本，不加载图片、媒体和其他外链，不跟随跳转。DNS 使用固定数量后台线程及独立等待上限；每次请求要求解析结果全部为公网地址，直接连接已校验的 IP 并用原域名验证 TLS，禁止代理和内网访问。HEAD 和 GET 各自有一个涵盖 DNS、连接、TLS、响应头和正文读取的整体截止时间，慢速持续响应也不能无限延长；该限时修正在上述首轮主机数据生成之后。只请求 HTTPS 443，默认只查根路径；指定 `--host` 后可用 `--path` 检查不含查询参数的已知静态路径。常规 HEAD 探针仅在 HEAD 200 后执行 GET；AMSI 探针独立请求根页 GET。非 HTML 或带内容编码的响应跳过，读取上限 32 KiB；不下载可执行文件或保存页面正文。重新运行会重新连接来源，结果及防护引擎版本可能发生变化。

这些检查是一次可复现的网络与静态元数据粗筛，不是完整安全审计；未执行脚本并不能证明不存在挂马，也未逐源验证搜索、详情、目录和正文。403、超时、域名解析失败和 TLS 错误应复查，不因单次结果批量删除。来源网页、解析规则和域名归属均会变化，后续应继续执行应用内完整链路检测，并在监管策略变化后复核已保存作品与缓存。
