## 3. Bug 明细

### AUD-01：HLS 跨类型同名 rendition group 被合并，离线丢轨

- **严重程度：P2 中；类别：解析逻辑、边界条件。**
- **位置：** [offline_rewriter.dart:89](../../lib/media/hls/offline_rewriter.dart#L89)，同文件第 94、109、111 行；调用入口 [hls_download.dart:188](../../lib/features/downloads/application/hls_download.dart#L188)。
- **描述与触发：** 合法 HLS 主清单同时声明 `TYPE=AUDIO,GROUP-ID="main"` 与 `TYPE=SUBTITLES,GROUP-ID="main"`，变体同时引用 `AUDIO="main",SUBTITLES="main"`。离线选择只保留其中一条 `EXT-X-MEDIA`，变体仍保留两个引用，造成独立音轨或字幕未被下载。
- **原因：** `groups` 仅以 `GROUP-ID` 建索引，然后每组只选一个默认项。HLS 的组身份包含媒体类型；不同类型可以使用相同组名。用字符串包含判断引用也未关联具体属性类型。
- **复现证据：** `AUD-01` 输入上述主清单，期望保留 2 条媒体声明，实际仅剩 AUDIO 的 1 条。运行的是生产 `HlsManifest.parse` 与 `selectOfflineVariant`。
- **修复建议：** 按 `(TYPE, GROUP-ID)` 建索引，解析变体的 AUDIO、SUBTITLES、VIDEO、CLOSED-CAPTIONS 属性后按类型选择；保留每个被引用组的必要声明。新增跨类型同名组、各组不同默认项及无 URI 的内嵌轨道用例。

### AUD-02：HLS Range 响应未核对请求偏移，错误分片被接受

- **严重程度：P2 中；类别：下载完整性、异常处理。**
- **位置：** [segment_fetcher.dart:47](../../lib/media/cache/segment_fetcher.dart#L47)，第 52、61 行；补充检查 [segment_store.dart:342](../../lib/media/cache/segment_store.dart#L342)。
- **描述与触发：** 请求 `Range: bytes=8-11`，来源返回 `206`、`Content-Range: bytes 0-3/16` 和 4 字节内容。当前缓存接受这个错误区间。离线重写去掉原 BYTERANGE 后，错误偏移的数据成为独立分片；缓存哈希只能证明下载后的字节未变化，不能证明它是所请求区间。
- **原因：** Fetcher 只要求 Range 请求返回 206，原样存储响应头。Store 仅核对响应区间自身的长度与实际长度，未比较请求和响应的 start/end，也没有强制要求有效的 Content-Range。
- **复现证据：** `AUD-02` 使用实际 `MediaHttpClient`、`SegmentFetcher`、`SegmentStore` 与本机 HTTP 服务；返回上述错位区间后，期望抛 `HttpException`，实际获得 `ResourceLease`。
- **修复建议：** 解析并校验单范围响应，要求起点/终点与请求一致（对合法尾部裁剪作明确处理）、区间和总长自洽、响应正文长度一致。拒绝缺失、畸形或错位的 Content-Range，并消费/取消响应体、清除失败缓存。

### AUD-03：漫画续传把仅有地址索引的坏章节视为完成

- **严重程度：P2 中；类别：离线完整性、恢复状态。**
- **位置：** [books_repository.dart:1059](../../lib/features/books/data/books_repository.dart#L1059)、[book_store_images.dart:205](../../lib/features/books/data/book_store_images.dart#L205)；结果消费 [book_download_coordinator.dart:178](../../lib/features/books/data/book_download_coordinator.dart#L178)。
- **描述与触发：** 章节图片地址索引尚在，但图片数据因损坏、缺失或不完整恢复而不可读。继续下载时该章节仍被排除；若范围内都被这样误判，任务直接显示 completed 并删除续传计划，实际离线阅读仍缺图。
- **原因：** 漫画分支直接返回 `savedImages()`；该方法仅 SELECT 地址索引键，不验证索引内容、分片存在性或图片可解码性。文本/音频的复用扫描已经做更深入校验，漫画没有对应检查。
- **复现证据：** `AUD-03` 在真实仓库写入地址索引但不写图片数据。`offlineImages()` 返回 null，`reusableDownloads()` 却返回该章节 ID。
- **修复建议：** 对所请求章节逐一验证非空地址表、完整分片、大小和图片可读性，并保留当前来源/权限校验；缺失或损坏章节进入重下队列。不能先删除旧数据再尝试下载；修复成功后原子替换。增加缺失一张、坏 base64、不可解码、空地址表及锁定中断用例。

### AUD-04：听书排队切换丢失 resume 参数

- **严重程度：P2 中；类别：异步状态、续播交互。**
- **位置：** [audiobook_controller.dart:90](../../lib/features/books/application/audiobook_controller.dart#L90)，第 37、82、106、155 行。
- **描述与触发：** 前一作品仍在加载时，打开另一部已有进度的听书，即使调用 `start(..., resume: true)`，新书仍从头播放。
- **原因：** `_pending` 只保存章节，未保存本次启动的 resume 语义；当前加载结束后调用 `_start(queued)`，落到默认 `resume: false`。因此后续读取到保存进度也不会触发 seek。
- **复现证据：** `AUD-04` 以受控引擎阻塞 A 的 open，给 B 保存 10 秒进度，再请求 B 续播。释放 A 后 B 成功打开、没有播放错误，但实际 `seeks` 为 `[]`。
- **修复建议：** 队列保存完整启动请求，至少包含作品/章节身份与 resume；消费时原样传递，并校验请求仍属于当前会话。覆盖快速 A→B、同书切章、连续替换待处理请求及默认续播/显式从头播放。

### AUD-05：导入的 EPUB/PDF 在书架类型筛选中均被归为 TXT

- **严重程度：P3 低；类别：界面分类、数据模型不一致。**
- **位置：** [book_shelf_view.dart:112](../../lib/features/books/presentation/book_shelf_view.dart#L112)，第 115、116、724 行；数据构造 [local_book_library.dart:58](../../lib/features/books/data/local_book_library.dart#L58)。
- **描述与触发：** 本地导入 EPUB 或 PDF 后，类型下拉只提供 TXT，不能按真实格式筛选；显示分类也错误。
- **原因：** 本地书身份 URI 为 `book:<文件内容摘要>`，不含原扩展名，原始文件另存为 `<book.id>.epub/pdf`。界面却以身份 URI 的后缀推断格式，EPUB/PDF 分支永远不命中。
- **复现证据：** `AUD-05` 真实导入测试 EPUB 并构建 `BookShelfView`。类型选项实际为 `['', '', 'TXT']`，没有 EPUB。PDF 使用相同身份构造和判断路径，其分类错误由静态调用链确认；本轮未启动 PDF 原生解码器复现。
- **修复建议：** 显式保存文档格式，并让界面读取格式元数据；已有条目可通过受控文档路径迁移识别。保持内容身份和书籍 ID 稳定，避免为补扩展名而破坏原进度/笔记引用。

### AUD-06：歌单播放强制在线匹配，跳过已完成的本地音乐

- **严重程度：P2 中；类别：离线优先级、界面调用链。**
- **位置：** [music_library_panel.dart:80](../../lib/features/music/presentation/music_library_panel.dart#L80)、[music_controller.dart:497](../../lib/features/music/application/music_controller.dart#L497)，第 500、545、549 行；标记转换 [music_track.dart:45](../../lib/features/music/domain/music_track.dart#L45)。
- **描述与触发：** 已下载歌曲加入歌单后，从歌单点击或“播放全部”会先在线匹配；断网、匹配失败或无歌手信息时，即便本地文件完整且可以直接打开，仍无法播放。
- **原因：** 歌单将所有歌曲转换为 `forPlaylistSearch()`，设置 `searchOnly`。播放器明确让 `searchOnly` 绕过 `downloads.localFor()` 和 `downloads.open()`，直接走在线候选解析。
- **复现证据：** `AUD-06` 创建真实可校验的本地下载，先确认 `downloads.open(track)` 成功，再以歌单转换后的同 key 歌曲选择播放；实际得到“未匹配到可播放的同名同歌手歌曲”，未创建有效播放。
- **修复建议：** 播放前优先查找并校验精确 key 的本地下载，再按现有保守规则匹配唯一的本地同录音；没有可用本地结果时才在线搜索。不要因此放宽模糊同名匹配或内容策略。

### AUD-07：音乐与电台同时恢复时形成跨队列循环等待

- **严重程度：P2 中；类别：并发安全、交互阻塞。**
- **位置：** [app_services.dart:142](../../lib/app/app_services.dart#L142) 和第 155 行；[music_controller.dart:764](../../lib/features/music/application/music_controller.dart#L764)、第 828 行；[radio_controller.dart:170](../../lib/features/radio/application/radio_controller.dart#L170)、第 210 行。
- **描述与触发：** 两个已初始化且暂停的播放器几乎同时收到恢复命令。音乐等待电台 pause；电台等待音乐 pause，命令互相排在对方恢复之后，直至操作超时。默认超时分别为音乐 25 秒、电台 20 秒，随后可能显示操作失败或丢弃引擎。
- **原因：** `beforePlay` 在各自串行命令队列内部执行，并 await 对方的串行 pause；缺少统一的音频播放权仲裁，形成 `音乐恢复 → 电台暂停 → 电台恢复 → 音乐暂停 → 音乐恢复` 等待环。
- **复现证据：** `AUD-07` 先顺序初始化/暂停真实两个控制器，再用 barrier 同时进入恢复的 beforePlay；仅将超时缩短为 200ms，得到“播放操作失败，请重试。”。没有把“初次同时选择”误当同一场景。
- **修复建议：** 在控制器外用统一仲裁器串行交接播放权，或提供不依赖对方恢复队列的可取消暂停流程。禁止持有本队列执行权时等待另一个可能反向等待的队列；用代次丢弃迟到恢复，确保最终最多一个会话播放。

### AUD-08：MP4 续传把任意 query 变化当作签名轮换，可能拼接不同资源

- **严重程度：P2 中；类别：资源身份、下载完整性。**
- **位置：** [mp4_download.dart:72](../../lib/features/downloads/application/mp4_download.dart#L72)，第 76、77、92、163 行。
- **描述与触发：** 旧部分数据来自 `/video?id=A`，恢复地址变成 `/video?id=B`。两个不同资源可以合法使用相同强 ETag 和长度；当前代码保留 A 的前缀并追加 B 的后缀。校验器可能拒绝混合文件，造成反复失败；若混合内容仍可解码，也可能留下错误媒体内容。
- **原因：** 实现注释承诺只容忍 query token rotation，但实际仅比较 origin/path，忽略所有 query。ETag 只在对应资源内有校验意义，不能证明不同 query 的表示是同一资源。
- **复现证据：** `AUD-08` 用本机受控服务，A 前缀为 `[1,2]`，B 完整内容为 `[5,6,7,8]`，共享 `"v1"`。实际输出 `[1,2,7,8]`。该复现使用透传媒体校验回调以观察字节拼接，**未证明这些人工字节可通过生产 FFmpeg 校验**；错误身份复用和混合输入已经确认。
- **修复建议：** 默认要求完整资源 URI 身份一致；只有来源明确提供稳定资源身份并确认签名刷新时，才允许受控的 token 参数变化。业务参数变化必须从零下载，不能全局删除 query 后判等。保留合法签名刷新续传用例。

### AUD-09：私密漫画替换同章图片时重复计入旧占用，错误报满

- **严重程度：P2 中；类别：容量边界、存储逻辑。**
- **位置：** [book_store_images.dart:154](../../lib/features/books/data/book_store_images.dart#L154)，第 160、164 行。
- **描述与触发：** 私密区接近 192MiB 限制，替换某章节的同一组图片，即使替换后总占用不会增长，也会抛出“私密离线图片空间已满”。修复/刷新该章节受到阻碍。
- **原因：** 先统计包含待替换旧章节的全部 `books_vault_data:*`，再加一份新图片估算；通过限额后才删除旧前缀。公共图片分支已经排除同章节旧分片，私密分支没有对应净额计算。
- **复现证据：** `AUD-09` 首先成功保存有效 PNG 到真实私密书籍，再以 SQLite `zeroblob` 模拟接近配额的其他已占空间，最后原样重存同一 PNG；实际抛上述空间异常。填充行只用于容量统计，不作为合法密文读取；未修改常量、未写入真实用户库。
- **修复建议：** 事务内计算“当前实际占用 − 本次会替换的旧密文占用 + 新密文实际占用”，同时考虑地址表、密文封装及编码开销。错误发生时保留原章节，覆盖等大、更小、更大替换及加密开销边界。

### AUD-10：FFprobe 阶段未响应取消，取消后 exporter 仍发布成功

- **严重程度：P2 中；类别：取消、资源生命周期。**
- **位置：** [ffmpeg_exporter.dart:147](../../lib/media/export/ffmpeg_exporter.dart#L147)，第 154、155、169 行；取消仅绑定在第 195 行的 `_execute()`。
- **描述与触发：** FFmpeg 重封装已完成，正在 FFprobe 探测输出时取消。探测没有绑定 cancellation，也没有应用层执行截止时间；返回后直到发布都不再检查 token，exporter 仍 rename 并返回成功。慢探测时取消按钮不能及时结束处理。
- **原因：** 取消监听只覆盖 `_execute()`；`_inspectLocal()` 未接收 token。发布前最后一次检查位于 await probe 之前，遗漏该异步间隔内的取消。
- **复现证据：** `AUD-10` 使用生产 `FfmpegExporter`，以方法通道夹具模拟成功编码和探测，并在探测阶段取消 token；期望 `RequestCancelled`，实际返回 `ExportResult`。这验证 Dart 控制流，不代表真实媒体探测性能。
- **影响边界：** 当前下载页和自动保存调用方在 exporter 返回后还会再次检查 token，因此**不能据此声称该路径一定把用户已取消的文件保存到最终外部位置**。已确认的是 exporter 继续发布中间结果，以及探测阶段不能及时取消；最终保存的授权遗漏另见 AUD-11。
- **修复建议：** 使用具有 session ID 的可取消探测，绑定 token 并设置明确的超时；探测返回和原子发布前再次检查 token。取消后应等待原生会话停止、释放监听并清理临时目录，避免让单纯超时留下后台会话。

### AUD-11：视频导出最终保存未持续校验内容授权

- **严重程度：P1 高；类别：授权边界、异步界面交互。**
- **位置：** [downloads_page.dart:312](../../lib/features/downloads/presentation/downloads_page.dart#L312)，第 293、309、310 行；[file_transfer.dart:54](../../lib/core/platform/file_transfer.dart#L54)，第 45、57 行；Android 相关 [MainActivity.kt:181](../../android/app/src/main/kotlin/dev/zeroplayer/zero_player/MainActivity.kt#L181)。
- **描述与触发：** 允许的视频完成重封装并打开保存位置对话框。此时来源被重新分类为受限内容，或监管/内容规则使该下载不再允许。监听器取消 token，但用户继续确认保存后，文件仍被写出。
- **原因：** 最后一次 `token.check()` / `requireAllowed()` 在调用 `FileTransfer.saveFile()` 之前。该调用没有传 `beforeWrite`，也没有传取消令牌。桌面选择器返回后直接 `file.copy()`；Android 通用保存通道在结果回调中直接 `input.copyTo()`，同样不关联该 token。取消 loopback session 无法撤回已经生成的本地文件。
- **复现证据：** `AUD-11` 构建真实 `DownloadsPage`、下载仓库和内容策略；原生编码器返回受控成功结果，系统文件选择器保持等待。将来源分类由普通改为 adult，确认 `downloads.allowed(task) == false` 后返回目标路径；目标文件实际仍存在，正确行为断言失败。被测权限链和文件复制均为生产代码。
- **修复建议：** 视频最终保存使用贯穿“选择位置→分块写入→提交”的授权/取消租约。桌面最少补充选择器返回后的 `token.check()` / `requireAllowed()`，并采用可取消流式暂存及无覆盖发布；Android 使用支持取消和创建文档清理的专用通道，可复用/推广 `ProtectedBookExport` 的两阶段设计。不能只在 Android 发起 picker 前加一次检查。增加选择器等待中策略撤销、写入中撤销和安全清理用例。

### AUD-12：导出采用 exists 后 rename，竞态下覆盖已有目标

- **严重程度：P2 中；类别：文件发布竞态、数据覆盖。**
- **位置：** [ffmpeg_exporter.dart:154](../../lib/media/export/ffmpeg_exporter.dart#L154)，第 155 行；已有可复用实现 [publish_file.dart:6](../../lib/core/platform/publish_file.dart#L6)。
- **描述与触发：** 最后一次 `target.exists()` 返回不存在后、`temporary.rename()` 执行前，另一写入方创建同名目标。当前 Dart/Windows rename 替换已有文件；前面的检查无法保证不覆盖。
- **原因：** 检查和发布不是一个原子“不替换”操作。实例内 `_active` 只约束该 exporter 实例内完全相同的路径字符串，不能阻止其他实例或外部写入方。
- **复现证据：** `AUD-12` 运行生产 exporter，用 `IOOverrides` 在第二次不存在观测之后、返回之前创建竞争文件，随后执行真实 Windows 文件 rename。原内容 `COMPETING EXISTING FILE` 被导出字节替换。所有路径位于独立临时目录。
- **影响边界：** 当前两处产品调用主要将 exporter 输出到应用中间目录；下载页最终位置另由 FileTransfer 选择。因此这是 exporter 的无覆盖发布契约错误，**不是已证明当前 UI 会无提示覆盖任意用户选择文件**，按 P2 而非 P1 评估。
- **修复建议：** 复用项目 `publishFile(temporary, target)` 的 Windows `MoveFileW` 无覆盖发布，目标已存在时保留它并报告失败。保留并发创建目标回归；如扩展多平台，逐平台验证原子无覆盖语义。
